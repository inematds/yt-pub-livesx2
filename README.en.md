# yt-pub-livesx2

**🇧🇷 [Português](README.md) · 🇺🇸 [English](README.en.md) · 🇪🇸 [Español](README.es.md)**

YouTube video publisher for N channels: **1 daemon, 1 database, 1 dashboard, N YAML files**.
Version 2 of [yt-pub-livesx](../yt-pub-livesx) — same job (livestream clips, imports, TikTok → YouTube),
without the 35 processes, 18 ports, and 17 copies of the code.

- **Why rebuild:** [`docs/ANALISE.md`](docs/ANALISE.md) — v1 numbers, findings, the other in-house publishers, discarded alternatives.
- **How it works:** [`docs/ARQUITETURA.md`](docs/ARQUITETURA.md) — job queue, credentials, channel-by-channel migration, phase 2.
- **Publish outside YouTube:** [`docs/PUBLICADORES.md`](docs/PUBLICADORES.md) — Blotato, Upload-Post, Postiz, Zernio, Ayrshare side by side.
- **Connect TikTok and Instagram:** [`docs/REDES-SOCIAIS.md`](docs/REDES-SOCIAIS.md) — step-by-step guide to destinations via Upload-Post.

## In 60 seconds

```bash
cd ~/projetos/yt-pub-livesx2
pip install -r requirements.txt            # cryptography + PyYAML (already installed on this machine)

scripts/importar-historico --todos          # reads the 17 v1 instances (read-only) -> canais/*.yaml + historico
./hub status                                # 17 channels, 12.466 published
./hub canais --token                        # which channels have valid OAuth (today: 12 OK, 5 dead)

./hub publicar video.mp4 --canal lives8 --titulo "Titulo" --dry-run   # validates everything, does not upload
./hub publicar video.mp4 --canal lives8 --titulo "Titulo" --agora     # uploads now
./hub publicar video.mp4 --canal lives8 --titulo "Titulo"             # queues; goes out at the next time in the YAML
./hub publicar video.mp4 --canal lives8 --titulo "T" --destinos uploadpost:instagram   # only one network
./hub status --destinos                     # queue and published items by channel AND network
scripts/setup-social --plano                # TikTok/Instagram: see docs/REDES-SOCIAIS.md
cp video.mp4 video.json entrada/lives8/                               # same, without CLI (n8n, scripts, human)

python3 hub.py                              # daemon (or systemd/yt-hub.service)
python3 dashboard/server.py 8200            # single dashboard
```

## Structure

```
hub.py                 daemon: schedules according to YAML times, runs overdue jobs (tick 30 s)
cli.py / ./hub         publicar | fila | status | canais [--token] | retry | jobs | tick
lib/
  db.py                schema + atomic job/clip claim
  runner.py            only executor; only one that publishes
  youtube.py           stateless publisher: resumable upload, thumbnail, list livestreams
  creds.py             .env + credentials.enc from the channel's config_dir (v1 format, nothing is copied)
  uploadpost.py        TikTok/Instagram and other publisher (Upload-Post API, local file)
  entrada.py           entrada/<canal>/*.mp4 (+ .json/.jpg) -> queue for each destination
  notify.py            Telegram in-process after publishing
  canais.py            canais/*.yaml
dashboard/             1 page, 1 port, all channels, retry button
scripts/
  importar-historico   v1 -> hub (read-only at source, idempotent)
  setup-social         creates profiles, declares destinations, and generates social network authorization links
  yt-clip yt-thumbnail yt-publish yt-auth    copied from v1 unchanged (phase 2)
canais/_exemplo.yaml   channel template
systemd/               yt-hub.service, yt-hub-dashboard.service (2 services total)
tests/test_jobs.py     15 tests without network
```

## One channel

```yaml
# canais/lives8.yaml — generated by importar-historico; edit as you like, the hub reloads automatically
destino_id: UCJxL11aomXJiBZga-JXylgQ
destino_nome: Inema Vibe
config_dir: /home/nmaldaner/projetos/yt-pub-lives8/config   # .env + credentials.enc stay HERE
horarios: ["08:10", "16:10"]                                 # 1 queued clip per time
privacy: public
telegram_chat_ids: ["7852460115"]
ativo: false                                                 # true when stopping yt-scheduler8
destinos:                                                    # optional; without this, YouTube only
  - youtube
  - destino: uploadpost:instagram
    horarios: ["19:00"]
```

Single global secret: `TELEGRAM_NOTIFY_BOT_TOKEN` (and optional dashboard password) in `<root>/.env` — see `.env.example`.

## Status (2026-09-06)

- Core is functional and tested: queue, idempotent jobs, mid-run restart, input, publisher with real dry-run
  (decrypts, refreshes token, builds metadata, stops before upload). No real upload has been made.
- 17 channels imported, all `ativo: false`: v1 continues publishing until you migrate channel by channel
  (plan in `docs/ARQUITETURA.md`).
- Multi-destination is ready and tested (28 tests): TikTok and Instagram via Upload-Post, queue and schedule
  per network. Needs a plan subscription and account authorization — see `docs/REDES-SOCIAIS.md`.
- Remaining phase 2 work (livestream cutting, thumbnail, TikTok scan, error alert) is designed, not built.

Version: `v2.0.0` (`lib/__init__.py`). Semver `vX.XX.YY`: minor carries the patch; only major resets.
